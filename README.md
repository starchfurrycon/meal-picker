# 选餐 · meal-picker

一句话进，一张卡片出。把模糊的「今天想吃什么」变成可搜索的关键词，在你自己的浏览器里读取
**各平台真实返回的价格**，按你的偏好加权排名，只呈现最优的那一份。

**没有任何模拟数据、估算价格或占位商家。** 拿不到实时价时它会直接告诉你，而不是编一个数字。

---

## 为什么需要装两个东西

先说清楚一件事，因为它决定了整个架构：

**「填个账号密码，工具就替你去各平台查实时价」在技术上不成立。** 这不是实现难度问题：

| 路径 | 实测结果 |
|---|---|
| 官方 API | 美团 / 京东 / 饿了么的开放平台都是面向商家与 ISV 的资质审批，没有面向消费者的实时比价接口 |
| 纯前端直连 | 浏览器 CORS 不允许；且各平台接口需要登录态与请求签名 |
| 服务端抓取 | 无登录态直连实测：美团返回 `418` + `riskLevel:199` 风控、饿了么老接口 `NO_URL_MATCHED`、京东要 `appid`、淘宝闪购 `RGV587` 滑块风控 |

复现方式（只做只读探测，不抓数据）：

```bash
node scripts/probe-realtime.mjs
```

所以唯一可行的路径是：**在你自己的浏览器里、用你自己的登录态，读取页面自己请求回来的数据。**
这既不是绕过风控（发起方就是真人真机），也不需要你把密码交给任何第三方。

于是架构是：

```
┌─────────────────────────────────────────────┐
│  你的浏览器                                  │
│                                             │
│  http://127.0.0.1:8765/  ← 工具页面          │
│         ↕ 同源，无跨域问题                    │
│  本地中继（relay/server.mjs）                 │
│         ↕ 采集器回传价格                      │
│  采集器用户脚本（跑在平台页面上）              │
│         ↕ 读取页面自己发出的搜索请求的响应      │
│  美团 / 淘宝闪购 / 京东 / 饿了么               │
└─────────────────────────────────────────────┘
```

工具页面必须由中继托管，因为线上是 https、中继是 http://127.0.0.1，
浏览器会把「https 页面请求本地 http」当成混合内容拦掉。

## 三步装好

### 1. 启动本地中继

需要 Node 18+。**零依赖，不用 npm install。**

从 [Releases](https://github.com/starchfurrycon/meal-picker/releases) 下载
`meal-picker-2.0.0.zip` 解压，然后：

```bash
node relay/server.mjs
```

也可以直接克隆仓库：

```bash
git clone https://github.com/starchfurrycon/meal-picker.git
cd meal-picker
node relay/server.mjs
```

Windows 上双击 `relay/启动.cmd` 更省事。

它会自动打开 <http://127.0.0.1:8765/>，这就是工具页面。

### 2. 装采集器脚本

浏览器装一个 **Tampermonkey**（油猴），然后打开：

<http://127.0.0.1:8765/install>

按页面提示点一下安装即可。装完工具栏会出现油猴图标。

> 没有中继、只想单独装采集器？从 Releases 下载 `meal-picker-collector.user.js`，
> 拖进油猴的「实用工具 → 安装」就行（默认连 `127.0.0.1:8765`）。

### 3. 在各平台登录一次

在浏览器里打开 **美团外卖**、**淘宝闪购**、**京东**，用你自己的账号登录。
浏览器会记住登录状态，之后不用反复登。

**然后就可以用了**：在工具页面输入一句话，工具会自动打开各平台的搜索页，
采集器在那些页面上读价格并回传，读完自动关掉那些标签页。

> 采集器不在线时工具不会瞎猜价格，会明确告诉你缺哪个平台、该做什么。

---

## 采集器到底做了什么

- 监听**页面自己发出**的搜索请求，读取它返回的 JSON。
  拦截的是页面与平台之间已有的通信，**不额外发起任何请求**。
- 认不出接口时，退一步读取页面上**已经渲染出来**的价格文字（DOM 兜底）。
- 把读到的价格 POST 到本机中继，**只存内存**，每轮比价开始时整体清空。
- 不上传任何数据到互联网，不碰你的账号密码，不改动页面上的任何内容。

它**不会**：代替你登录、破解验证码、伪造请求签名、绕过风控、自动下单。

### 关于稳定性

各平台页面结构随时会变，采集器可能某天认不出某个平台的数据。这时它不会猜，
只会如实报告「没读到」。适配配置集中在 `collector/meal-picker-collector.user.js`
顶部的 `ADAPTERS` 里，是按平台分组的声明式配置，改起来不用动逻辑。

中继的 `/api/debug` 会保留最近收到的原始样本，方便为新平台补适配。

---

## 它算出来的价格是什么价

**列表价 + 页面可见的优惠与配送费，不是你结算页的最终价。**

外卖的最终价取决于你实际选了什么、用什么券、有没有凑满减，这只有在下单页才能确定。
工具做的是把各平台**可比的报价**拉到同一把尺子上，帮你判断「去哪家点更划算」，
卡片上的下单按钮会直接跳到对应平台的搜索结果页，最终价以那边为准。

---

## 加权是怎么算的

八个因子，各自归一化到 0–1，再按你的权重加权求和。权重可在「设置 → 口味」里拖拽调整，
会自动归一化，不需要你凑成 100。

| 因子 | 含义 | 默认权重 |
|---|---|---|
| 价格 | 到手价越低越好 | 26 |
| 折扣力度 | 相对原价的降幅 | 18 |
| 优惠券 | 可用券与满减额度 | 12 |
| 商家评分 | 店铺综合评分 | 14 |
| 商家诚信 | 评价真实度与经营稳定度 | 10 |
| 口味匹配 | 与你这句需求的贴合度 | 10 |
| 送达速度 | 预计配送时长 | 6 |
| 会员权益 | 会员价与专属券 | 4 |

推荐理由与卡片文案**全部由结构化数据生成，不调用大模型**。

## 大模型只做一件事

把你那句模糊的话**转写成可搜索的关键词**。它不给答案、不参与比价、不生成推荐理由。

不开启也完全能用 —— 内置了一套轻量语义转写（识别品类、口味、预算、人数、忌口、时间），
离线、零成本。

开启后（浏览器直连 OpenAI 兼容接口，支持自定义 Base URL 与模型名）刻意做得省：

- system 提示词 600 字符出头
- 输出字段名压到 2 字符（`kw` / `k` / `t` / `b` / `p` / `a`）
- 强制 `response_format: json_object`，`max_tokens: 180`，`temperature: 0.2`
- 同一句话命中内存缓存，不重复计费
- 结果页脚显示本次 token 与估算费用；设置页有今日/累计用量

接口报错时自动回退到内置转写，流程不中断。

## 隐私

- 价格只存中继内存，每轮比价开始时清空，不落盘、不复用缓存。
- **不需要填平台密码。** 实时采集用的是你浏览器里已有的登录态，
  设置页里的「账号」只是给你自己看的备注。
- 大模型 API Key 走 AES-GCM 256 加密后落盘（PBKDF2-SHA256，31 万次迭代），
  默认设备密钥自动解锁，也可设口令保护（口令不落盘）。
- 非安全上下文（`file://` 且无 WebCrypto）会降级为混淆存储，界面会**明确告知**这不是加密。
- 导出数据默认不含密钥；「彻底清除」会移除设置、用量、凭据与设备密钥。
- 中继只监听 `127.0.0.1`，不对外暴露，空闲 30 分钟自动退出。

## 三种打开方式

| 方式 | 实时比价 | 说明 |
|---|---|---|
| **中继托管** `node relay/server.mjs` → `http://127.0.0.1:8765/` | ✅ | 推荐。功能完整 |
| 单文件版 `dist/meal-picker.html` 双击打开 | ✅ | 也能连本地中继（需先启动中继 + 装采集器） |
| 在线版 <https://starchfurrycon.github.io/meal-picker/> | ❌ | https 页面被浏览器禁止请求本地 http，只能浏览界面 |

在线版保留下来是为了让人先看看界面长什么样；真要用来比价，请用前两种。

### 下载与校验

发行文件在 [Releases](https://github.com/starchfurrycon/meal-picker/releases)：

| 文件 | 说明 |
|---|---|
| `meal-picker-2.0.0.zip` | 推荐：单文件版 + 目录版 + `relay/` + `collector/` + 插画源文件 |
| `meal-picker-collector.user.js` | 采集器脚本（只想单独装它的话） |
| `meal-picker.html` | 单文件版 |
| `SHA256SUMS.txt` | 上面几个文件的校验和 |

校验：

```bash
# macOS / Linux
shasum -a 256 -c SHA256SUMS.txt

# Windows
Get-FileHash .\meal-picker.html -Algorithm SHA256
```

> 单文件版里嵌了构建时间戳，所以**你本地 `npm run build` 出来的哈希不会和发行版一样**。
> 要核对请用发行版自己的 `SHA256SUMS.txt`。

## 开发

```bash
npm start              # 启动中继（= node relay/server.mjs）
npm run build          # 打包到 dist/（单文件 + 目录版 + zip + 校验和）
npm test               # 逻辑冒烟测试（含真实启动中继跑 API）
npm run e2e            # 真实浏览器端到端（自动起中继 + 灌入假采集器数据）
npm run e2e:llm        # LLM 分支端到端（本机假接口，不产生费用）
npm run e2e:dist       # 发行包自检
npm run probe          # 实时数据可行性探测（只读）
```

浏览器端到端自检需要 **Node 22+**（用全局 `WebSocket` 连 CDP）与本机 Chrome/Edge；
缺任意一个会自动跳过而不是报错。

全部自检都不使用任何真实 API Key，也不产生任何费用。

### 目录结构

```
web/                    工具本体（零构建，原生 ESM）
  index.html            应用外壳 + 内联图标 sprite
  styles/               设计令牌与全部样式
  js/
    app.js              主控：转写 → 采集 → 加权 → 出卡
    realtime.js         实时采集编排（登记任务 / 轮询取价 / 超时处理）
    adapters.js         数据源解析与外部记录规范化
    engine.js           八因子加权排名 + 无 LLM 的推荐理由
    taste.js            内置轻量语义转写
    llm.js              LLM 关键词转写（省 token 版）
    crypto.js           凭据保险箱
    store.js            设置 / 用量 / 凭据持久化
    views.js  ui.js  settings.js  art.js  catalog.js  util.js
relay/
  server.mjs            本地中继（零依赖，只用 Node 内置模块）
  install.html          采集器安装引导页
  启动.cmd              Windows 双击启动
collector/
  meal-picker-collector.user.js   采集器用户脚本
assets/dishes/          13 张菜品插画源文件 + 预览页scripts/                构建与自检脚本
```

### 自定义数据接口

不想用采集器，也可以接自己的后端。设置 → 平台 → 价格数据从哪来 → 自备接口。

前端会向该地址 POST：

```json
{
  "platform": "meituan",
  "keywords": ["麻辣香锅", "麻辣烫"],
  "kinds": ["hotpot"],
  "tastes": ["spicy"],
  "budget": 45,
  "party": 2,
  "avoid": ["香菜"],
  "raw": "想和朋友吃点够味的鱼，两个人，别超过五十",
  "member": true
}
```

期望返回候选数组（或 `{ "offers": [...] }`）：

```json
[{
  "merchant": "店名",
  "rating": 4.7,
  "reviewCount": 2381,
  "good": [{ "text": "好评原句", "tag": "份量足" }],
  "bad": [{ "text": "差评原句", "tag": "偏咸" }],
  "packages": [{
    "id": "任意唯一 id",
    "name": "套餐名",
    "dish": "套餐名",
    "art": "hotpot",
    "basePrice": 42,
    "shippingFee": 4,
    "packingFee": 1,
    "deals": [{ "kind": "coupon", "label": "满 40 减 12", "amount": 12, "threshold": 40 }],
    "finalPrice": 35,
    "etaMin": 32,
    "monthlySales": 890
  }]
}]
```

`art` 可选值：`noodles` `rice` `burger` `pizza` `hotpot` `bbq` `dumpling` `sushi` `salad` `dessert` `congee` `crayfish` `default`。
